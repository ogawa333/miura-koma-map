# 三浦港 コマ地図メーカー

ZIPを解凍し、中身のファイルとdataフォルダをリポジトリ直下にアップロードします。
Settings → Pages → Deploy from a branch → main → /(root) → Save で公開します。

出発地・目的地・経由地から、交差点だけのコマ地図を生成します。CPとミッション、交差点付近の登録済み看板・史跡などに対応します。
コマ地図の生成にはインストールやAPIキーは不要です。

## 手元の画像をコマ地図に追加（Google API・課金不要）

各コマの「確認・追記」を開き、「手元の画像に差し替え」で対象の目印・道路標識を選んで画像を追加し、「追記を保存」を押してください。図の対象イラストが画像に変わります。目印は図に表示される先頭4件、道路標識は各標識が対象です。目印のないコマでは、先に目印や標識を追記して保存し、もう一度開いてください。

JPEG・PNG・WebP（1ファイル10MB以下）に対応し、長辺480px以下のJPEGに縮小して保存します。画像は外部へアップロードせず、ブラウザの自動保存、保存用JSON、参加者表示、印刷・PDFに含まれます。「画像を解除」で元のイラストへ戻せます（「追記を保存」で確定）。変更せず閉じると画像の変更は破棄されます。「手動追記を解除」はそのコマの画像も解除します。

画像が多いとブラウザの自動保存容量を超える場合があります。画面上部に自動保存失敗が表示された場合は「データ保存」でJSONをダウンロードしてください。JSONの読み込み上限は15MBです。保存したJSONには写真も含まれるため、共有前に内容を確認してください。

## Google Street View画像

OSM登録済みの目印・道路標識の「画像」リンクで確認画面を開きます。
画像表示には、課金設定とStreet View Static APIを有効にしたGoogle CloudのAPIキーが必要です。
APIキーはブラウザの確認画面に入力します。コードやGitHub、JSONに書き込まないでください。
ブラウザ用APIキーはウェブサイト制限とStreet View Static APIのAPI制限を設定し、日次の割り当て上限も確認してください。
https://developers.google.com/maps/documentation/streetview/get-api-key
https://developers.google.com/maps/documentation/streetview/usage-and-billing

画像はGoogleから必要なときに表示します。画像は保存データやPDFに含めません。
OSMで位置が登録されていても、その看板が画像に写っているとは限りません。

設定と作成した地図はブラウザ内に保存されます。公開先を移す場合は旧アプリで「データ保存」、新アプリで「読み込む」を使います。
各利用者の設定を他の利用者と自動共有する機能はありません。

## サンプルコース：三崎港・宮川北側まち歩きチャレンジ

うらり発着で、海南神社・見桃寺・栄児童公園・宮川神明社・宮川神明社の北側にある原稲荷神社を巡ります。CPはこの5か所です。前半3か所は現在地から直線距離が近い順、後半2か所はランダムに訪問します。同梱データでは約6.03〜6.04kmで、後半の順序によりコマ数が変わります。どちらの順序でも城ヶ島へ入らない経路を検証しています。途中で先のCPの付近を通過することはありますが、ミッションは指定した訪問順で行います。

保存済みのコースは自動置換しません。サンプルボタンで新コースを選んでください。既存の手動追記はリセットされるため、必要なら先に「データ保存」してください。道路の接続は同梱OSMデータに基づき、現地の通行可否を保証するものではありません。

## 経由地の訪問順

「前半は近い順・後半はランダム」では、出発地とゴールを固定します。経由地の数の半分（端数切上げ）まで、現在地から直線距離が最も近い未訪問地点を順に選び、残りをFisher–Yates法でシャッフルします。各地点間の実際の道順は従来どおりA*法で計算します。直線距離による順序なので、徒歩距離全体の最小化ではありません。後半が1地点以下なら順序は変わりません。

「自動生成」を押すたびに再抽選します。同じ順になる場合もあります。表示の絞り込み切替・再読み込み・JSON読み込み・旧データの再計算では順序を変えません。「入力した順番」も選べます。旧JSONでは入力順を維持します。CP番号とミッションは並べ替えた順に追従します。

## 交差点の絞り込みと道なり

「交差点の表示」で「全交差点（絞らない）」と「道なりを省略（チャレンジ）」を即時切替できます。ルートは変えず、コマ番号と前のコマからの距離、全体図の番号を選択した表示に合わせて再計算します。すべてのコマを保持するので、切替で写真・追記は消えません。CP、経由地と重なる交差点、最初と最後のコマ、手動追記のあるコマは残します。旧JSONは全表示を初期値にし、交差点判定を再計算して取り込みます。

新しいモデルコースは省略ありで生成します。既存コースを勝手に置換しません。

省略交差点では道なりに進み、次のコマと交差点の形が一致する場所で矢印に従います。進み方の優先順位は、直進、センターライン・グリーンベルトの連続、道幅、路面、緩い角度、勾配、Y字路で停止線・標識のない方です。この案内は省略版の印刷・PDFにも載ります。

自動判定は、この7項目すべてを認識するものではありません。道路形状から明確な直進を選び、分岐では全候補に明示的な幅・舗装の情報がある場合に連続性を比較し、角度差も確認します。同程度のY字路、急角度、歩行できない枝道が見える場所、交差点や直近の枝ノードに標識が登録された場所は残します。センターラインの連続、グリーンベルト、勾配の連続や停止線の向きは現データでは自動判定せず、道路名だけで継続と判断することもありません。看板・目印があるだけでは省略を止めませんが、写真や注意書きを手動追加するとそのコマは残ります。作成者が全交差点版と現地を照合してください。

判定ロジックのテストは `node tests/routing.test.cjs` で実行できます（外部依存なし）。

看板・目印の自動関連付けは交差点から直線距離10m以内に限定します。道路標識・信号の範囲は従来の28mです。旧保存データは経路と目印を再計算して取り込み、手動の画像・追記を保持します。保存済みコースのCP数は自動変更せず、新しいサンプルを選択した場合に5か所になります。

## 似た交差点の省略防止

省略する各交差点を「次の表示コマ」と比較します。進入方向をそろえて、枝道の交差点から8m・20m付近の向きを照合し、各角度差が20度以内で対応する場合を類似候補とします。ルート矢印、標識、写真は比較に使いません。左右反転は行わず、同じ場所でも進入方向に応じて判定します。道の本数の一致を必須条件とします。三差路・四差路・五差路はそれぞれ別の形として扱い、同じ本数の場合だけ角度を比較します。本数が判明していて異なる場合は角度情報が不足していても非類似です。本数が同じで角度情報が不足する場合や、本数そのものが不明な場合は、区別できないものとしてコマを残します。

似た省略コマを一つ表示へ戻すたびに区間を分割し、再判定を繰り返します。右左折だけでなく、次の表示が直進コマでも比較します。復帰したコマには、作成者向けに「後続の○○地点と形が似ているため表示」と理由を出します。参加者表示や印刷には理由を出しません。番号・コマ間距離・全体図は最後に振り直します。

形状の一致は現地での視認性を保証しません。角度差20度は初期の判定値であり、現地照合を前提とします。計算した形状の範囲外にある交差点群や、データ上で離れた点に分割された一つの交差点は別途下見が必要です。
